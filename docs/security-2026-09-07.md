## Concrete release order — production approval required

1. Verify commit, GitHub checks and both Worker deployment IDs. Both `thinkin-about-money` and legacy `spese-tracker` currently bind the same D1 database. Freeze any other writers before proceeding.
2. Put both Workers into maintenance before schema changes. The new entrypoint's `MAINTENANCE_MODE=true` blocks API requests (including cron HTTP) with503/no-store and skips scheduled handlers. Deploying the reviewed code in maintenance is safe before the new schema because no application handler is reached. Use explicit per-Worker configs so the legacy name cannot overwrite the wrong service. Test503 on APIs and no scheduled writes on both. Asset-first serving can still display static pages; maintenance guarantees stopped application writes, not a503 for every asset. Drain already-running requests/jobs from the old deployments and verify writer quiet before the final export; a new version cannot cancel handlers already in flight. `BANK_SYNC_ENABLED=false` alone is insufficient.
3. Export a final private backup after all writers are stopped, re-run the offline preparator and record its hash. The earlier backup does not replace this final check. Capture the D1 recovery point and Worker versions for rollback.
4. Execute only the generated baseline SQL as a controlled batch, then verify the seven names and token index. The baseline registrar intentionally has no `IF NOT EXISTS`/`INSERT OR IGNORE` masking an unexpected state. `wrangler d1 migrations list --remote` can itself create the tracking table, so it is not a read-only investigation command before this step.
5. Verify only0008–0010 are pending, then apply using Wrangler migrations. Each migration's successful completion persists; a failure does not imply the entire chain rolled back. Keep maintenance enabled on any failure.
6. Validate upgraded schema, indexes/constraints, tracking, counts/totals, old columns, sequences, FK and integrity. Configure banking secrets and preserve ENCRYPTION_KEY separately. Resend configuration or explicit acceptance of disabled password recovery remains outstanding. Run `preflight` against the actual target; it must pass except an explicitly documented unavailable optional service. Its column substring checks are only a quick diagnostic; the offline schema comparison and migration rehearsal provide the structural evidence.
7. Reopen only the current Worker with `MAINTENANCE_MODE=false`, bank automation stillfalse. Leave the legacy Worker in maintenance to prevent duplicate scheduled jobs; verify API/auth, manual transaction, import retry and first scheduled recurrence run. Existing recurrence arrears may be generated by that first run.
8. Perform Fineco/Revolut consent in the user's real session, limited manual sync, candidate review and replay check. Trade Republic is absent from authenticated IT/DE catalogue. No real-bank restoration claim until this succeeds.

Rollback: remain in maintenance and stop both writers. After0008, restoring only old code is not sufficient: old budget code is incompatible with nullable month/year. Restore the matching database recovery point/private backup together with its previous Worker version, validate integrity and counts before reopening. Never overwrite post-release user writes automatically; assess recovery if writes already resumed.
